# Implementation notes

## One server application

`ServerModel` owns `EmbeddedStreamingEngine` and `WorkspaceServer`. It starts the bundled engine first, waits for its certificate-pinned, authenticated local API to respond, then starts the TLS workspace listener. Either component failing stops the combined service. Stop and application termination close listeners, shells, uploads, and the child process. The server runs directly as `Contents/MacOS/nocturne-stream-host`, a managed subprocess. Its libraries are in `Contents/Frameworks` and its assets in `Contents/Resources/assets`. There is no nested Sunshine.app, independent app launcher, or separate server installation. Nocturne never searches `/Applications` for another engine or opens a web configuration page.

The embedded engine has its tray disabled, UPnP disabled, and administrative access restricted to the local PC. The app generates a fresh random administrative password on each start and writes only its salted SHA-256 representation in the engine's required format. No plaintext administrative credential appears in process arguments or a configuration file. Its certificate is loaded from Nocturne's private configuration directory and pinned exactly for local API calls; redirects and other certificates are rejected.

App state lives in `~/Library/Application Support/Nocturne/Engine` with mode 0700. Configuration/credential files are mode 0600. The engine handles its own private-key file protection. The default desktop app and required environment node are generated on first start. Existing application configuration is preserved.

GameStream uses its standard ports beginning at 47984/47989; local administration uses HTTPS 47990. Nocturne's workspace TLS listener uses TCP 48555 and Bonjour `_nocturne._tcp`. Separate transport ports are internal to the same server app. Port conflicts fail startup instead of silently attaching to another Sunshine instance.

## Pairing

QR payloads use the `nocturne://pair` format to carry invitation version, host, workspace port, display name, a 32-byte transport secret, and a 32-byte enrollment token. Only the in-app scanner accepts these invitations: there is no registered URL handler, copy/paste pairing UI, or manual address/PIN path. After a scan the client authenticates the workspace, saves the invitation in Keychain, discovers that host's streaming endpoint, and starts the upstream certificate pairing handshake. The protocol's internal video challenge goes through the authenticated workspace channel; it is never displayed or entered by the user. The Mac matches a pending video request by the authenticated connection's IP; ambiguous matches fail closed and ask the user to scan again with one device at a time. It does not approve arbitrary pending clients.

Workspace protocol 4 retains the requirement for a fresh challenge-response after the TLS-PSK handshake and before any operation. The client signs a SHA-256 challenge bound to the TLS exporter with its streaming RSA private key. The Mac verifies the signature using that certificate, then authorizes its SHA-256 identity against the saved workspace roster or a single-use QR enrollment token generated by the Mac. A streaming certificate alone no longer registers a new workspace identity. Names and IP addresses are display/routing information, never identity. The TLS binding prevents a former device that knows the transport PSK from relaying another device’s signature onto its own session. Old clients fail closed with an update message.

`WorkspaceDeviceStore` persists public identity metadata and unfinished removals in a private JSON file outside the shared folder. Enrollment tokens live only in memory, expire after five minutes, and are consumed by one identity. Restarting or removing a device invalidates an unused token. Registered workspace identities and approved streaming pairings remain usable on upgrade. A streaming-only device must scan a QR code before gaining workspace access.

`ServerDevice` joins saved engine certificates, workspace identities, and authenticated connections by certificate fingerprint. Duplicate names and shared IP addresses remain separate; multiple sessions from one identity share one row. The Mac refreshes the list every 1.5 seconds and shows saved devices while stopped. “Connected” reflects the workspace transport; the engine API provides paired certificates but no per-device active-video status, so streaming-only devices are labeled “Paired”.

Individual removal blocks the workspace identity first, closes all of its channels, PTYs, and uploads, waits for its in-flight automatic pairing operation, then [disables and unpairs](https://github.com/LizardByte/Sunshine/blob/v2026.1018.5342/src/confighttp.cpp) each matching streaming certificate. Disabling uses the engine’s per-certificate session termination; unpairing alone does not close existing video sessions when another device is paired. Other devices’ certificates, keys, connections, and terminals remain unchanged. Interrupted removals remain blocked across restart and visible for retry. Scanning a fresh QR code can restore access after a completed removal.

`NocturnePairingTrust` records explicit video approval in a device-local Keychain item, keyed by host UUID and bound to the server and client certificates. A new receipt requires both the cryptographic handshake callback and an authenticated workspace approval response, in either arrival order. The selected host must have an active QR-authorized workspace before a new handshake starts and when approval is recorded. Existing Core Data certificates and discovery's paired flag do not migrate into approval. Both library access and controller creation check the receipt. Callback objects bind each attempt to its host; forgetting, cancelling, or losing QR authorization prevents late callbacks from creating trust. The Swift model cancels delayed stream presentation and forgets the linked streaming host when the workspace pairing is removed.

The runtime pin is `v2026.1018.5342` (official prerelease). In the previous `v2026.914.233613` build, repeating a successful PIN handshake added a duplicate client certificate, and exact-identity authorization then rejected that device. The [upstream registration fix](https://github.com/LizardByte/Sunshine/blob/v2026.1018.5342/src/nvhttp.cpp) replaces records for that same certificate after a verified handshake. Nocturne uses the corrected executable directly, with no wrapper application and no certificate-verification bypass.

The Mac exposes no manual PIN approval controls. Engine request listing and approval are private implementation details used only by the authenticated workspace pairing path. Reset first revokes engine client certificates and then rotates the workspace key, disconnecting sessions; individual device removal also revokes that identity's workspace access.

## Client

The SwiftUI client wraps the pinned native Objective-C streaming implementation, retaining its video/audio decoding, touch mapping, keyboard, mouse, and controller support. It uses the original Core Data host and certificate persistence. The integration excludes the original entry point and supplies a native SwiftUI scene. The bridge explicitly calls `SDL_SetMainReady`, which the replaced entry point previously handled, before audio initialization.

The full-screen stream workspace is retained outside the size-dependent navigation layout. `StreamDisplaySize` converts its video area's points and display scale into even pixel dimensions, preserving aspect ratio under a 4096-pixel bound. Match device is the new-install default; saved fixed preferences are preserved. Rotation, Split View, Stage Manager, and tool-panel changes coalesce for 600 ms before renegotiation. A stable `StreamSession` replaces its video controller only after the previous global decoder has fully stopped, retaining workspace/terminal state.

Deterministic source overlays add completion-based stop to upstream `Connection`, `StreamManager`, and `StreamFrameViewController`. A cancelled operation cannot subsequently create a connection, and stop callers wait until `LiStopConnection` completes before starting the next stream. Repeated stop is idempotent. A separate overlay recalculates the upstream touch-control geometry. Dependency checkouts remain pristine; bootstrap rejects unexpected source shapes and commits.

Touch and Trackpad are explicit choices in Settings and the stream menu, backed by the existing `absolutePointer` preference for compatibility. Switching updates the active touch handler and zoom container without replacing the stream controller. Input overlays release cancelled touches, serialize rapid trackpad clicks on the main queue, and invalidate pending tap releases when switching modes or stopping. Touch handlers hold the stream view weakly so retired handlers cannot keep it alive.

Physical mouse input uses GCMouse only when the scene actually has pointer lock; otherwise UIKit handles position, buttons, and scrolling inside the stream. Raw callbacks ignore unlocked events so local controls do not also click the remote computer. Each UIKit pointer touch remembers its pressed buttons, allowing either release-mask convention and button chords. Pointer-lock changes, cancellation, accessory removal, and stream shutdown release held buttons. Native client tests exercise the real touch handlers and mouse callbacks at their transport boundary without requiring a live stream; physical Bluetooth behavior still needs device verification.

## Managed displays

Workspace protocol 4 adds `displayPrepare`, `displayHeartbeat`, and `displayRelease`. Only an authenticated session receives the display capability, and only when **Headless virtual monitor** is enabled. `DisplaySessionManager` validates 320–4096 even pixel dimensions and 30/60/120 Hz, and grants a single lease bound to both the transport connection UUID and stream UUID. Another connection cannot resize, renew, or release it, even with the same device identity. The client renews every five seconds; a separate 20-second timer, socket cleanup, device removal, Stop, and failed preparation all release the lease. Initial configuration has a separate 50-second deadline, with a 60-second client request timeout, to allow the framebuffer and encoder to become ready. Late asynchronous preparation is invalidated by a revision token. Match device refuses to start without authenticated display control, with instructions to enable the virtual monitor or choose a fixed video resolution.

The macOS `DisplayBridge` isolates private CoreGraphics interfaces behind runtime checks. Server startup and display configuration require an unlocked console session; display configuration can stall while macOS is locked. A virtual Retina display advertises the physical dimensions and half-size logical mode, then explicitly selects and verifies the matching pixel mode. WindowServer caches a display's mode list, so resolution changes create a replacement display before releasing the previous framebuffer. Virtual-monitor mode creates a 1920×1080 framebuffer before Sunshine probes its encoder, even with physical monitors connected. By default it does not change the primary display or submit physical-layout changes. Only the separate monitor-off opt-in captures and changes the physical layout; the virtual framebuffer and WindowServer's headless placeholder are excluded from that snapshot.

Before changing displays, the controller snapshots IDs/UUIDs, modes, origins, and mirroring. Optional monitor disabling uses `CGSConfigureDisplayEnabled`/`SLSConfigureDisplayEnabled` only after the virtual display exists; this makes macOS move windows onto the remaining desktop. Disabled monitors disappear from enumeration, so restoration retains their IDs, re-enables them first, resolves fresh mode objects, and restores the original layout. Mode publication is asynchronous and restoration retries while monitors wake. A headless session retains its virtual framebuffer between streams while the server is running.

Display ownership runs in an internal recovery process using the same signed app executable (`--nocturne-display-worker`), with no separate application to install. Bounded JSON messages pass over private inherited pipes; no network listener or secret is added. The worker owns the CoreGraphics objects and runs AppKit's event loop. On parent-pipe EOF it restores physical displays before releasing the virtual display, retrying if a monitor takes time to return. This is needed because Apple's documented [`forAppOnly`](https://developer.apple.com/documentation/coregraphics/cgconfigureoption/forapponly) lifetime behavior does not reliably undo the private display-enabled bit after an abrupt process exit. Killing the entire process group, logging out, and machine power loss are outside this worker's recovery guarantee.

The engine still runs directly from `Contents/MacOS/nocturne-stream-host`. The display worker returns the actual CoreGraphics display ID at startup and after resizing. The parent binds Sunshine's `output_name` to that ID. Sunshine reads this option at startup, so replacing the framebuffer restarts only the embedded video engine and waits for its authenticated readiness response before acknowledging `displayPrepare`. The workspace connection, terminal sessions, shared files and saved device certificates survive. A selected physical monitor bypasses managed display control. The virtual display stays alive between leases so the engine never retains a deleted target. Virtual display interfaces are not public App Store APIs; their use is confined to the directly distributed Mac server. Reference implementations: [Chromium's virtual display utility](https://chromium.googlesource.com/chromium/src/+/HEAD/ui/display/mac/test/virtual_display_util_mac.mm) and [displayplacer's monitor configuration](https://github.com/jakehilborn/displayplacer/blob/master/src/DisplayPlacer.c).

## Native appearance

Both applications share `NocturneTheme.swift`. `PrimaryButtonStyle` and `NocturneGlassButtonStyle` delegate to Apple's native glass button styles on iOS/macOS 26+, with native bordered fallbacks. Custom stream controls use `glassEffect`; adjacent controls use `GlassEffectContainer`. Content cards use separate quiet surfaces instead of stacking glass materials. System navigation supplies the iPhone floating tab bar, iPad/Mac sidebars, toolbars, and sheet controls.

The `nocturne.appearance` preference selects System, Light, or Dark independently in each application. Semantic text colors and dynamic AppKit/UIKit color tokens follow that appearance. Reduce Transparency removes decorative background gradients and makes content panels opaque. The terminal uses fixed, contrasting canvas colors. Its only Escape/Tab/Control/arrow accessory is SwiftTerm’s own keyboard. Tab controls have separate accessible select/close actions, selected-state traits, horizontal overflow, and keyboard focus transfer. Each terminal surface subscribes independently; hiding a workspace disables its input/resize callbacks.

On macOS, Appearance lives in a native SwiftUI [Settings scene](https://developer.apple.com/documentation/swiftui/settings), opened from Nocturne Server → Settings… or ⌘,. A SettingsLink also appears in the menu bar extra. The main toolbar contains Pair a device; it has no Appearance control.

## Workspace transport

`NocturneKit` provides bounded JSON framing, TLS-PSK, Keychain storage, request deadlines, transfer state, and adaptive layout rules. Every connection requires a versioned hello. `NocturneHostKit` provides the host listener, `openat`/`O_NOFOLLOW` folder access, atomic no-overwrite uploads, real PTYs, and embedded-engine management. Partial transfers are cleaned up on disconnect or permission revocation. Up to eight workspace connections and two uploads per connection are accepted. Terminal lifetime belongs to `WorkspaceServer` through `TerminalRegistry`, independently of those connections. Up to eight terminal tabs (running or ended) are retained per authenticated device certificate. Every list/attach/input/resize/close operation checks that owner; reconnecting cannot bypass the limit.

Protocol 3 adds terminal listing/attachment and per-tab metadata. Every output event carries a byte offset. Attachment atomically subscribes the connection and returns the retained suffix; the client appends only missing bytes, or resets its renderer when the requested offset has expired. The replay buffer is bounded to 512 KiB per tab and fits within the frame limit after JSON/base64 encoding. The server keeps draining PTYs while detached, and drains final output before marking an exited tab ended. Nothing is persisted to disk, and neither shells nor output survive a server restart.

Disconnect only removes that socket’s output subscriptions. Explicit tab close terminates one shell; Terminal permission revocation, Stop/Quit, or device removal closes the corresponding registry entries, including detached ones. A client reconnect lists and attaches existing tabs without opening replacement shells. Client buffers and selection survive a transport disconnect and are cleared when forgetting or switching the paired server.

The iOS app has no cloud service or account dependency. Its UIKit scene delegate disconnects the workspace transport when backgrounded, leaves server-owned shells running, reconnects and restores tabs when active, and keeps credentials out of ordinary preferences. A production distribution should use consistent Developer ID/device signing; these local builds are development artifacts.
