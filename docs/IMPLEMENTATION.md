# Implementation notes

## Integrated Mac client

The Mac app links `NocturneMacClient` and presents its saved-host library under Computers. `MacClientModel` owns outgoing sessions independently of `ServerModel`: disconnecting a viewer never stops local hosting. A Security-generated RSA identity and the saved host roster use separate Mac-client Keychain accounts. Pairing accepts the same expiring, single-device invitation as the QR scanner, via an explicit Copy pairing code/Paste pairing code flow. No credentials enter UserDefaults or scene restoration.

Mac desktop streaming is an optional protocol-v4 extension advertised as `desktop-stream-v1`. `DesktopSessionManager` reserves one global desktop-control lease before capture starts and checks connection/session ownership for input, resize, heartbeat, and close. Disconnect, revocation, failed capture, expiry, and server shutdown release capture and held input. The host only installs this manager when Screen sharing is enabled. Older iOS clients continue using their existing capabilities and protocols.

`NativeDesktopHost` captures an existing display with ScreenCaptureKit, uses the shared bounded H.264 encoder and fragmented-frame assembler, and sends bounded 48 kHz Float32 stereo packets. Audio excludes the current process to prevent feedback when a Mac views and hosts simultaneously. `DesktopCaptureSession` retains the requested display and control lease while following the main display at loginwindow. Locked video uses AVFoundation screen capture, as in the embedded streaming engine, without enumerating shareable windows. Lock/unlock replaces the media source and releases held input; input pauses until the new target is ready. Logout/inactive sessions remain unavailable. Heartbeat replies report current dimensions and lock state without overwriting the viewer's display selection. System audio resumes with ScreenCaptureKit after unlocking.

`MacDesktopSession` connects through the existing TLS-PSK/device-proof workspace transport, including authenticated remote tunnels; native media needs no GameStream UDP tunnel or new public port. AppKit presents video in an `AVSampleBufferDisplayLayer`, maps input through aspect-fit geometry, and releases input on focus loss. Mac desktops default to matching the viewer's content size and backing scale through the same authenticated display lease used by iPad. `displayPrepare` returns the actual framebuffer ID. The client closes the previous native capture before replacing that framebuffer, opens a new video session on the returned ID, and renews the stable display lease separately from each video session. This rejects late video from a replaced capture. Disconnect cleanup stops native capture before restoring the display. Physical monitor selection remains explicit and uses the monitor's original aspect ratio. Missing adaptive support reports an actionable error instead of silently selecting a physical monitor.

`MacAppsModel` independently authenticates the app browser, pages the existing app-window catalog, and launches applications. Each selected window opens its own `MacDesktopSession` using the `app-windows-v1` operations, with window/application identity validation, a heartbeat, bounded video/input, and resize forwarding. `MacClientModel` deduplicates scenes by host/window and keeps their connections separate from the desktop and browser. Closing a scene releases only that capture; application termination closes all outgoing connections. App streams contain only window video; system sound is available through Desktop. A locked host directs app users to Desktop to unlock before opening windows.

`MacAppWindowController` presents app streams in borderless AppKit windows that explicitly accept keyboard focus. A 14-point transparent strip contains only the drag handle; its context menu supplies fit/reconnect/full-screen/close actions. The host window's own chrome is part of the captured image, so there is no second local title bar or toolbar. Fixed-size host windows advertise optional `isResizable: false` metadata; their local viewers preserve the video aspect ratio while scaling. Older window metadata remains decodable. Accessibility resize rejection falls back to the window's current geometry; closed-window and permission errors still propagate. Any position/size Nocturne owns is restored on release if the user has not changed it.

## One server application

`ServerModel` owns `EmbeddedStreamingEngine` and `WorkspaceServer`. It starts the bundled engine first, waits for its certificate-pinned, authenticated local API to respond, then starts the TLS workspace listener. Either component failing stops the combined service. Stop and application termination close listeners, shells, uploads, and the child process. The server runs directly as `Contents/MacOS/nocturne-stream-host`, a managed subprocess. Its libraries are in `Contents/Frameworks` and its assets in `Contents/Resources/assets`. There is no nested Sunshine.app, independent app launcher, or separate server installation. Nocturne never searches `/Applications` for another engine or opens a web configuration page.

The embedded engine has its tray disabled, UPnP disabled, and administrative access restricted to the local PC. The app generates a fresh random administrative password on each start and writes only its salted SHA-256 representation in the engine's required format. No plaintext administrative credential appears in process arguments or a configuration file. Its certificate is loaded from Nocturne's private configuration directory and pinned exactly for local API calls; redirects and other certificates are rejected.

App state lives in `~/Library/Application Support/Nocturne/Engine` with mode 0700. Configuration/credential files are mode 0600. The engine handles its own private-key file protection. The default desktop app and required environment node are generated on first start. Existing application configuration is preserved.

GameStream uses its standard ports beginning at 47984/47989; local administration uses HTTPS 47990. Nocturne's workspace TLS listener uses TCP 48555 and Bonjour `_nocturne._tcp`. Separate transport ports are internal to the same server app. Port conflicts fail startup instead of silently attaching to another Sunshine instance.

## Pairing

QR payloads use the `nocturne://pair` format to carry invitation version, host, workspace port, display name, a 32-byte transport secret, and a 32-byte enrollment token. Only the in-app scanner accepts these invitations: there is no registered URL handler, copy/paste pairing UI, or manual address/PIN path. After a scan the client authenticates the workspace, saves the invitation in Keychain, discovers that host's streaming endpoint, and starts the upstream certificate pairing handshake. The protocol's internal video challenge goes through the authenticated workspace channel; it is never displayed or entered by the user. The Mac matches a pending video request by the authenticated connection's IP; ambiguous matches fail closed and ask the user to scan again with one device at a time. It does not approve arbitrary pending clients.

Workspace protocol 4 retains the requirement for a fresh challenge-response after the TLS-PSK handshake and before any operation. The client signs a SHA-256 challenge bound to the TLS exporter with its streaming RSA private key. The Mac verifies the signature using that certificate, then authorizes its SHA-256 identity against the saved workspace roster or a single-use QR enrollment token generated by the Mac. A streaming certificate alone no longer registers a new workspace identity. Names and IP addresses are display/routing information, never identity. The TLS binding prevents a former device that knows the transport PSK from relaying another device’s signature onto its own session. Old clients fail closed with an update message.

`WorkspaceDeviceStore` persists public identity metadata and unfinished removals in a private JSON file outside the shared folder. Enrollment tokens live only in memory, expire after five minutes, and are consumed by one identity. Restarting or removing a device invalidates an unused token. Registered workspace identities and approved streaming pairings remain usable on upgrade. A streaming-only device must scan a QR code before gaining workspace access.

`ServerDevice` joins saved engine certificates, workspace identities, and authenticated connections by certificate fingerprint. Duplicate names and shared IP addresses remain separate; multiple sessions from one identity share one row. The Mac refreshes the list every 1.5 seconds and shows saved devices while stopped. “Connected” reflects the workspace transport; the engine API provides paired certificates but no per-device active-video status, so streaming-only devices are labeled “Paired”.

Individual removal blocks the workspace identity first, closes all of its channels, PTYs, and uploads, waits for its in-flight automatic pairing operation, then [disables and unpairs](https://github.com/LizardByte/Sunshine/blob/v2026.1028.122642/src/confighttp.cpp) each matching streaming certificate. Disabling uses the engine’s per-certificate session termination; unpairing alone does not close existing video sessions when another device is paired. Other devices’ certificates, keys, connections, and terminals remain unchanged. Interrupted removals remain blocked across restart and visible for retry. Scanning a fresh QR code can restore access after a completed removal.

`NocturnePairingTrust` records explicit video approval in a device-local Keychain item, keyed by host UUID and bound to the server and client certificates. A new receipt requires both the cryptographic handshake callback and an authenticated workspace approval response, in either arrival order. The selected host must have an active QR-authorized workspace before a new handshake starts and when approval is recorded. Existing Core Data certificates and discovery's paired flag do not migrate into approval. Both library access and controller creation check the receipt. Callback objects bind each attempt to its host; forgetting, cancelling, or losing QR authorization prevents late callbacks from creating trust. The Swift model cancels delayed stream presentation and forgets the linked streaming host when the workspace pairing is removed.

The runtime pin is `v2026.1028.122642` (official prerelease). In the previous `v2026.914.233613` build, repeating a successful PIN handshake added a duplicate client certificate, and exact-identity authorization then rejected that device. The [upstream registration fix](https://github.com/LizardByte/Sunshine/blob/v2026.1028.122642/src/nvhttp.cpp) replaces records for that same certificate after a verified handshake. Nocturne builds that source revision with its encoder overlay, with no wrapper application and no certificate-verification bypass.

The engine overlay omits `AV_CODEC_FLAG_LOW_DELAY` for VideoToolbox only. That flag enables Apple's low-latency rate controller, which can drop entire frames when the bitrate budget is too small. Sunshine uses the input timestamp as the transmitted frame number; missing outputs therefore look like network loss to Moonlight, causing further keyframe requests and sustaining recovery. Real-time hardware encoding and `max_b_frames = 0` remain enabled. Other encoders retain their original flags. `Sources/StreamingEngine/EncoderFlags.h` is shared by the generated source overlay and the native regression.

The Mac exposes no manual PIN approval controls. Engine request listing and approval are private implementation details used only by the authenticated workspace pairing path. Reset first revokes engine client certificates and then rotates the workspace key, disconnecting sessions; individual device removal also revokes that identity's workspace access.

## Client

The SwiftUI client wraps the pinned native Objective-C streaming implementation, retaining its video/audio decoding, touch mapping, keyboard, mouse, and controller support. It uses the original Core Data host and certificate persistence. The integration excludes the original entry point and supplies a native SwiftUI scene. The bridge explicitly calls `SDL_SetMainReady`, which the replaced entry point previously handled, before audio initialization.

Desktop streams present `StreamHostingController` directly so UIKit reads the pointer-lock request from the controller that owns the full-screen workspace. A video controller nested inside an ordinary SwiftUI cover cannot supply that preference on its own. The request requires a ready stream, a connected mouse, and the session's Lock pointer option; controls, tools, backgrounding, and dismissal release it. Raw mouse movement/buttons require both the controller's capture permission and the scene's actual lock state, preserving UIKit fallback when iPadOS declines capture. Command–Shift–M is handled locally before keyboard forwarding and opens controls in the originating window. Focus/lock transitions release held keys and buttons. The workspace host survives video-controller replacement during resizing.

Playback overlays keep the video display link active in common run-loop modes, including touch tracking, so scrolling and dragging cannot suspend video consumption. `StreamVideoPacing.h` compares network arrival gaps with source presentation gaps. When excess jitter exceeds one frame, it primes a bounded cushion and releases frames at the negotiated cadence instead of presenting each network burst together. The cushion is at most 150 ms and 12 frames, leaving room in the upstream 15-frame decoder queue. A stable connection retains the user's original zero/one-frame pacing preference. The policy resets for each stream.

Audio starts with a 20 ms PCM cushion. Arrival gaps can raise it to at most 160 ms for the current stream; an underrun rebuilds that cushion. The pending-packet discard limit grows with it, so radio scheduling bursts are not repeatedly discarded. The decoder callback never sleeps waiting for SDL output. Stalled output is cleared if it would exceed the current target plus 40 ms, giving an absolute 200 ms queue limit. Late packets still advance the stateful Opus decoder before their PCM is discarded. Limits use sample duration, so changing the negotiated Opus packet size does not multiply latency. Pinned dependency sources remain unchanged.

The full-screen stream workspace is retained outside the size-dependent navigation layout. `StreamDisplaySize` converts its video area's points and display scale into even pixel dimensions, preserving aspect ratio under a 4096-pixel bound. Match device is the new-install default; saved fixed preferences are preserved. Rotation, Split View, Stage Manager, and tool-panel changes coalesce for 600 ms before renegotiation. A stable `StreamSession` replaces its video controller only after the previous global decoder has fully stopped, retaining workspace/terminal state.

Deterministic source overlays add completion-based stop to upstream `Connection`, `StreamManager`, and `StreamFrameViewController`. A cancelled operation cannot subsequently create a connection, and stop callers wait until `LiStopConnection` completes before starting the next stream. Repeated stop is idempotent. A separate overlay recalculates the upstream touch-control geometry. Dependency checkouts remain pristine; bootstrap rejects unexpected source shapes and commits.

Touch and Trackpad are explicit choices in Settings and the stream menu, backed by the existing `absolutePointer` preference for compatibility. Switching updates the active touch handler and zoom container without replacing the stream controller. Input overlays release cancelled touches, serialize rapid trackpad clicks on the main queue, and invalidate pending tap releases when switching modes or stopping. Touch handlers hold the stream view weakly so retired handlers cannot keep it alive.

Physical mouse input uses GCMouse only when the scene actually has pointer lock; otherwise UIKit handles position, buttons, and scrolling inside the stream. Raw callbacks ignore unlocked events so local controls do not also click the remote computer. Each UIKit pointer touch remembers its pressed buttons, allowing either release-mask convention and button chords. Pointer-lock changes, cancellation, accessory removal, and stream shutdown release held buttons. Native client tests exercise the real touch handlers and mouse callbacks at their transport boundary without requiring a live stream; physical Bluetooth behavior still needs device verification.

## Managed displays

Workspace protocol 4 adds `displayPrepare`, `displayHeartbeat`, and `displayRelease`. Only an authenticated session receives the display capability, and only when **Headless virtual monitor** is enabled. `DisplaySessionManager` validates 320–4096 even pixel dimensions and 30/60/120 Hz, and grants a single lease bound to both the transport connection UUID and stream UUID. Another connection cannot resize, renew, or release it, even with the same device identity. The client renews every five seconds; a separate 20-second timer, socket cleanup, device removal, Stop, and failed preparation all release the lease. Initial configuration has a separate 50-second deadline, with a 60-second client request timeout, to allow the framebuffer and encoder to become ready. Late asynchronous preparation is invalidated by a revision token. Match device refuses to start without authenticated display control, with instructions to enable the virtual monitor or choose a fixed video resolution.

The macOS `DisplayBridge` isolates private CoreGraphics interfaces behind runtime checks. Server startup and display configuration require a signed-in console session, including a locked desktop. `NocturneSession.h` shares this policy with capture selection; missing, logged-out and inactive sessions remain unavailable. A virtual Retina display advertises the physical dimensions and half-size logical mode, then explicitly selects and verifies the matching pixel mode. WindowServer caches a display's mode list, so resolution changes create a replacement display before releasing the previous framebuffer. Virtual-monitor mode creates a 1920×1080 framebuffer before Sunshine probes its encoder, even with physical monitors connected. By default it does not change the primary display or submit physical-layout changes. Only the separate monitor-off opt-in captures and changes the physical layout; the virtual framebuffer and WindowServer's headless placeholder are excluded from that snapshot.

The macOS engine overlay keeps the requested display ID separately from the capture target. While the console session is locked, `CaptureDisplay.h` selects `CGMainDisplayID()`, where loginwindow renders the password field; a newly created secondary virtual display is otherwise blank. During capture, a bounded-frequency session check returns `capture_e::reinit` when the effective target changes. Sunshine rebuilds capture, encoding and absolute-pointer geometry on the existing video connection. Unlocking restores the requested monitor, while a headless Mac whose virtual monitor is already main needs no switch. The normal paired keyboard path enters the password into macOS; there is no password storage, privileged login helper, automatic login or FileVault support.

Physical-layout changes retain a separate unlocked-session guard because primary-display/monitor-off transactions can stall under loginwindow. A locked preparation creates its virtual framebuffer without changing the physical layout; the monitor-off preference is applied on the next preparation after unlock. A lock arriving during mode publication also skips the pending physical-layout change.

Before changing displays, the controller snapshots IDs/UUIDs, modes, origins, and mirroring. Optional monitor disabling uses `CGSConfigureDisplayEnabled`/`SLSConfigureDisplayEnabled` only after the virtual display exists; this makes macOS move windows onto the remaining desktop. Disabled monitors disappear from enumeration, so restoration retains their IDs, re-enables them first, resolves fresh mode objects, and restores the original layout. Mode publication is asynchronous and restoration retries while monitors wake. The virtual framebuffer stays alive until physical-display restoration succeeds, then is released with the lease.

Display ownership runs in an internal recovery process using the same signed app executable (`--nocturne-display-worker`), with no separate application to install. Bounded JSON messages pass over private inherited pipes; no network listener or secret is added. The worker owns the CoreGraphics objects and runs AppKit's event loop. On parent-pipe EOF it restores physical displays before releasing the virtual display, retrying if a monitor takes time to return. This is needed because Apple's documented [`forAppOnly`](https://developer.apple.com/documentation/coregraphics/cgconfigureoption/forapponly) lifetime behavior does not reliably undo the private display-enabled bit after an abrupt process exit. Killing the entire process group, logging out, and machine power loss are outside this worker's recovery guarantee.

The engine still runs directly from `Contents/MacOS/nocturne-stream-host`. The display worker returns the actual CoreGraphics display ID at startup and after resizing. The parent binds Sunshine's `output_name` to that ID. Sunshine reads this option at startup, so replacing the framebuffer restarts only the embedded video engine and waits for its authenticated readiness response before acknowledging `displayPrepare`. The workspace connection, terminal sessions, shared files and saved device certificates survive. A selected physical monitor bypasses managed display control. The next lease creates a fresh virtual display and selects its ID before streaming resumes. Virtual display interfaces are not public App Store APIs; their use is confined to the directly distributed Mac server. Reference implementations: [Chromium's virtual display utility](https://chromium.googlesource.com/chromium/src/+/HEAD/ui/display/mac/test/virtual_display_util_mac.mm) and [displayplacer's monitor configuration](https://github.com/jakehilborn/displayplacer/blob/master/src/DisplayPlacer.c).

## Native appearance

Both applications share `NocturneTheme.swift`. `PrimaryButtonStyle` and `NocturneGlassButtonStyle` delegate to Apple's native glass button styles on iOS/macOS 26+, with native bordered fallbacks. Custom stream controls use `glassEffect`; adjacent controls use `GlassEffectContainer`. Content cards use separate quiet surfaces instead of stacking glass materials. System navigation supplies the iPhone floating tab bar, iPad/Mac sidebars, toolbars, and sheet controls.

The `nocturne.appearance` preference selects System, Light, or Dark independently in each application. Semantic text colors and dynamic AppKit/UIKit color tokens follow that appearance. Reduce Transparency removes decorative background gradients and makes content panels opaque. The terminal uses fixed, contrasting canvas colors. Its only Escape/Tab/Control/arrow accessory is SwiftTerm’s own keyboard. Tab controls have separate accessible select/close actions, selected-state traits, horizontal overflow, and keyboard focus transfer. Each terminal surface subscribes independently; hiding a workspace disables its input/resize callbacks.

On macOS, Appearance lives in a native SwiftUI [Settings scene](https://developer.apple.com/documentation/swiftui/settings), opened from Nocturne → Settings… or ⌘,. A SettingsLink also appears in the menu bar extra. The main toolbar contains Pair a device; it has no Appearance control.

## Client microphone

Workspace protocol 4 negotiates `microphone-pcm-v1` as an additive capability. Older peers remain compatible for their existing features. Microphone start/audio/stop operations require the usual TLS-bound certificate authentication plus the host's separate, default-off microphone permission. `MicrophoneSession` owns one connection-scoped, server-generated lease. Frame sizes, monotonic sequence numbers, and lease identity are validated before the driver sees audio. Removing a device, closing its socket, revoking permission, or stopping the server releases the lease; two seconds without audio also expires it.

The client opens a dedicated authenticated `WorkspaceConnection` with terminal restoration disabled. It requests iOS microphone permission only on an explicit unmute after video/audio initialization completes. `AVAudioEngine` voice processing runs in a play-and-record/voice-chat session, leaving streamed playback active. The current iOS input route supplies the built-in, wired/USB, or Bluetooth HFP microphone. A persistent `AVAudioConverter` downmixes/resamples to 48 kHz mono signed 16-bit little-endian PCM, split into 960-sample (20 ms) packets. Capture buffering and unacknowledged sends are each limited to six frames. A one-second acknowledgement timeout closes the connection, and a capture watchdog catches a stopped tap. Audio is never written to disk.

`ClientMicrophone.stop()` invalidates asynchronous permission/start callbacks, removes the tap, cancels capture and pending networking, and restores playback mode. Scene backgrounding, stream exit/reconfiguration, workspace disconnect, interruptions, route changes, and media-service resets all mute it. There is no persisted or automatic unmute. The upstream audio initializer finishes before the stream-ready callback enables the microphone control; microphone capture stops before upstream stream shutdown can reset the shared audio session.

The Mac feeds `NocturneMicrophone.driver` through Core Audio custom properties using `MicrophoneBridge`; it never plays received voice through the default output. This input-only HAL plug-in publishes a fixed 48 kHz mono Float32 device called **Nocturne Microphone**. A timestamp-indexed ring lets multiple recording apps read the same samples without consuming one another's audio. Missing frames, mute, and an expired producer produce silence. The render callback uses a nonblocking try-lock and performs no allocation or IPC. Producer writes are bound to the originating process, buffered latency is bounded, and a two-second timeout releases a crashed producer.

`package-microphone-driver.sh` builds the driver into the server's Resources; release signing signs it before the outer app. The Sharing installation action copies that specific bundle into `/Library/Audio/Plug-Ins/HAL` with administrator authorization and readable root-owned permissions. It asks the user to restart the Mac instead of restarting the system audio service. No driver is installed during builds or tests. `test-microphone-driver.sh` loads the compiled plug-in in a test process under AddressSanitizer/UBSan; this does not claim that coreaudiod, Discord, or physical iOS audio routes were tested.

## Apple Files

`Sources/FileProvider` implements a [browsing File Provider extension](https://developer.apple.com/documentation/fileprovider/nsfileproviderextension), embedded in the iOS app as `app.nocturne.client.files`. `FilesExtension` handles native item URLs and placeholders, and delegates network operations to `HostFileProvider`. `FilesIntegration` registers one nonreplicated domain per paired workspace after authenticated file capability negotiation, updates it on reconnect, and removes it on forget or disabled sharing. Each domain's account is stored under its own Keychain item, and the extension reads only the item matching its domain. Domain operations are serialized and generation-checked so a delayed registration cannot win over forgetting or replacing the Mac.

The extension shares `group.app.nocturne.client` and the containing app’s existing Keychain access group. `FilesProviderAccount` keeps the transport invitation, certificate, and PKCS#1 private key in Keychain with device-only, after-first-unlock protection. The QR enrollment token is stripped. The app saves the authenticated address for Files after pairing and reconnecting; the extension also rediscovers the paired workspace independently if that address becomes stale. The extension proves the same streaming device identity on its own TLS socket for each operation, verifies the domain identity, checks the current file permission, and never restores terminal sessions. It can reconnect an enrolled identity but cannot enroll a device. No private keys are stored in the app group, domain metadata, or ordinary preferences.

Canonical path identifiers and validated immediate-child listings map the shared root and nested folders into Files. Files advertises reading and folder enumeration only. Downloads reuse bounded, cancellable transfers, recheck metadata before completing to reject a file changed during transfer, and move complete contents into the location’s document storage. Releasing a file cancels any transfer, evicts its local contents, and restores a native placeholder. Unsolicited local edits are discarded. File sizes and subsecond modification times determine content versions. Persistent metadata snapshots support synchronous item lookups and track additions, modifications, and deletions across extension launches; expired anchors trigger re-enumeration. The working set refreshes visited folders instead of recursively crawling the entire shared root. Host `openat`/`O_NOFOLLOW` checks remain the filesystem boundary. Root listings open independent directory descriptions so repeated refreshes do not inherit an exhausted `readdir` cursor.

Extension invalidation and `Progress.cancel()` cancel pending operations, including TLS readiness and active chunk transfers. An unreachable host becomes a Files connectivity error; a removed identity requires pairing again. Files may retain copies that users already downloaded.

The extension uses the on-demand browsing API rather than requiring filesystem replication. During development, the iOS 27 simulator’s replicated provider accepted remote metadata but failed to create local placeholders with `libfssync.DocumentWharfError.cannotSetMetadata` / `EPERM`. The nonreplicated provider passed the same native Files listing and document-preview check.

## Individual app windows

Workspace protocol 4 advertises the additive `app-windows-v1` capability. `NativeAppWindowHost` discovers launchable bundles in system, local, network, and user application directories, plus running regular applications. Catalog requests return 64 entries at a time; icons are fetched separately. Launch and capture resolve IDs against that catalog instead of accepting arbitrary executable paths. Window IDs are checked against the application's actual running process on every open.

Each iPad app window is a separate UIKit scene, authenticated workspace socket, `AppWindowStreamModel`, display layer, and host capture lease. Restoration activities store only the server fingerprint, application/window IDs, and title; pairing keys remain in Keychain. The fingerprint selects that window's own paired Mac, so windows from several Macs can stream at once. A window socket reuses the library connection's remote tunnel only when both belong to the same Mac. Each socket rediscovers the paired host before connecting, so a restored scene can recover a stale address without the library being active. Opening the same target activates its existing scene. Scene background/disconnect releases only its own capture; library-scene lifecycle cannot stop sibling app streams. Four windows per certificate and eight host-wide are permitted. A connection-scoped UUID is required for resize, input, heartbeat, and release. Pending opens reserve a window before suspension and cannot acquire capture after disconnect. Removal closes all that device's sockets; heartbeats expire abandoned captures after 20 seconds.

Capture uses ScreenCaptureKit's [`desktopIndependentWindow` filter](https://developer.apple.com/documentation/screencapturekit/sccontentfilter/init(desktopindependentwindow:)), without a desktop fallback or additional child windows. Each stream owns a VideoToolbox H.264 encoder. Only one frame is encoded/sent at a time; congested sockets drop unencoded capture frames. Each submission is drained on the encoder queue so software encoders cannot wait for a later frame before producing output. Access units are bounded at 4 MiB and fragmented into 192 KiB pieces to fit the existing 1 MiB JSON framing limit. The client validates/reassembles one bounded frame and displays it with its own `AVSampleBufferDisplayLayer`. No app stream touches Moonlight's global decoder, input hooks, or Sunshine display configuration. Audio is disabled for this path.

Resize messages distinguish logical scene points from encoded pixels. Accessibility sets the selected Mac window's real size; ScreenCaptureKit and the encoder use its resulting dimensions, respecting app minimum sizes. App video accepts even dimensions below the desktop minimum of 320 pixels, preserving small windows and their aspect ratio on 1× displays. Rapid scene changes are coalesced, and capture updates in place. Exact Accessibility/WindowServer identity uses the runtime-checked `_AXUIElementGetWindow` bridge; unsupported systems and non-resizable/non-accessible windows fail explicitly. Capture and input require the Mac's existing Screen Recording/Accessibility grants. Direct touches defer the left-button press until a tap or drag resolves, preventing long presses and two-finger scrolling from triggering a left click. Pointer events carry click counts, current modifier flags, the selected window ID, and target process; keyboard input focuses and verifies that exact Accessibility window before posting to its process. Cleanup clears modifier flags while releasing held input and restores the original size only if the user has not resized it independently.

`AppWindowTests` exercises lease isolation, ownership, limits, fragmentation, stale releases, delayed-open disconnects, real catalog/icons, and authenticated independent TLS sockets with device revocation. The opt-in native test creates two real Mac windows, captures H.264 while occluded, resizes one independently, and injects text through the actual input path. iPad client tests cover native scene independence/restoration and actual H.264 display-layer decoding and reconfiguration. Physical iPad Stage Manager, accessory behavior, and sustained network performance still require device validation.

## Agent chats

The additive `chats-v1` workspace capability is advertised only when the separate Mac-side `HostPermissions.chats` switch is enabled. Authenticated `chatProviders`, `chatList`, `chatLoad`, `chatNew`, `chatPrompt`, `chatCancel`, and `chatPermission` requests share the existing TLS-PSK workspace connection. `chatEvent` carries streamed text, completed items, permission prompts, and final status. Chat contents are cleared from the client model when the connection changes, preventing history or late responses from crossing paired Macs.

`ChatHostSession` owns one lazy provider process per authenticated socket. Switching providers, changing configuration, disconnecting, revoking permission, and server shutdown close the process and fail its pending JSON-RPC continuations. An agent that ignores cancellation is terminated after ten seconds. Only locally saved `ChatAgentConfiguration` entries can launch processes; network requests select provider IDs and never provide executable paths, arguments, environment variables, or working directories. Commands run directly through `Process`, without shell interpolation. Provider stdout is newline-delimited JSON with a 32 MiB bound; stderr is drained without forwarding potentially private diagnostics.

Codex uses [App Server](https://developers.openai.com/codex/app-server) to discover all local source kinds and model providers, browse archived threads, read legacy rollouts or paginated items, and resume only when the user sends a prompt. New and resumed turns use workspace-write sandboxing and on-request approvals. ACP v1 providers negotiate capabilities before `session/list` and `session/load`, replay user/agent chunks, and use `session/new`, `session/prompt`, `session/cancel`, and `session/request_permission`. Agents own authentication and Mac-side tools; Nocturne does not advertise client filesystem or terminal execution capabilities. Unsupported agent requests receive an explicit JSON-RPC error. Claude Code is preconfigured through `claude-agent-acp`; other ACP agents are configured in Mac Sharing settings.

Conversation and transcript pages use opaque connection-local cursors. Long messages are split at Unicode scalar boundaries, with byte budgets sized to remain within the workspace frame even after JSON escaping. Permission decisions validate the request, active session, and exact option ID. Revocation closes providers independently of terminal/file permissions. The installed-Codex test reads history only; fixture tests cover prompts and tool approvals without paid inference or real file mutations.

## Developer workspace

The native chat follows the supplied T3 reference screens: a black sidebar and charcoal canvas, local Working/Snoozed/Settled organization, bottom search/composer and a floating tool rail. `ChatNavigationState` namespaces presentation preferences and drafts by paired-Mac identity and provider. Snoozes expire by time. `PullRequestInboxModel` discovers at most twenty loaded thread directories and four remotes per checkout, deduplicates forge URLs and paginates PRs. Cross-thread requests accept status/PR-list reads only; the host still resolves each directory from the authenticated agent's thread.

On iOS 27.1+, `ChatBarEnvironment` reads Apple's `toolbarVerticalEdge` environment value. When a vertical bar is preferred, the chat registers symbol-labelled navigation/actions with its existing `NavigationStack` and `ToolbarOverflowMenu`, instead of adding a custom rail inside the safe area. The system owns edge placement, reserved camera/status regions, overflow and keyboard compression; no device-name, screen-size or hinge-angle guess selects the bar. The content removes the custom rail's padding, and composer options depend on available conversation width. Other bar contexts retain the reference layout.

`developer-actions-v1` gates staged commits, non-force branch pushes, PR creation and activity. Commit previews hash HEAD, branch and full staged blob IDs. Hosting writes use structured JSON and the Mac's existing CLI identity. GitHub comments/reviews and Azure PR threads supply Activity; their payloads are bounded. Agent review guides and helpers use the selected chat with bounded actual PR context, preserve its draft and keep existing approval routing. Watching polls only while the PR view exists and the scene is active. No remote mutation or paid inference is used by fixture tests.

The feature reference was [T3 Code](https://github.com/pingdotgg/t3code/tree/d1c4b52b7c7c7e1b7637ec47e4c959ff0c2d8d99), especially its GitManager, worktree setup and separate GitHub/Azure DevOps PR providers. Nocturne implements these workflows natively in Swift rather than embedding the reference UI.

`developer-workspace-v1` is advertised with authenticated Agent chats. `chatOptions` and `chatConfigure` expose agent-provided selectors. Codex 0.164.0 uses paged `model/list`, thread `model`/`reasoningEffort` metadata, and `thread/settings/update` with `model`/`effort`. Values are checked against the catalog; changing models also selects that model's advertised default effort. ACP `configOptions` flatten grouped select values and apply through `session/set_config_option`; `config_option_update` notifications update the UI. No model IDs or effort levels are hard-coded. Codex's bounded `turn/diff/updated` event powers the latest-agent diff, independently of working/staged/base-branch comparisons.

`chatRepository` resolves the selected conversation's directory on the Mac and never accepts an arbitrary project root from the phone. `RepositoryService` discovers the Git root and uses NUL-separated porcelain status/name-status/worktree records. Diff commands disable external diff/textconv, use literal pathspecs and terminate options before paths. Stage/Unstage affect a named path only. Worktrees use validated branch/base refs and a Mac-owned destination; only a checkout in Git's current worktree list can be used for `chatNew`. Canonical paths keep macOS `/var` aliases from breaking the binding. Creating a worktree never switches or cleans the original checkout.

`SharedFolder`'s descriptor-relative, no-follow access is reused for bounded UTF-8 editing. Revision hashes reject stale saves; edits use a temporary sibling, preserved mode, fsync and atomic rename. `.git` paths and traversal are rejected. Repository mutation requests are disabled while the agent/voice session is active; access revocation cancels running project tasks. `DeveloperCommand` uses literal argv, bounded stdout/stderr, cancellation and deadlines; no shell interpolation or interactive credential prompts are used. Project commands and agent processes clear inherited Git directory/index overrides so the conversation's checkout determines their repository.

`ForgeService` parses GitHub HTTPS/SSH/Enterprise and Azure DevOps HTTPS/SSH/legacy remotes without forwarding URL credentials. GitHub uses `gh api`; Azure uses `az devops invoke` with explicit organization/project/repository routes and API 7.1, preserving the DevOps extension's authentication. Lists and changed-file pages are bounded; GitHub file patches are explicitly previews. Azure diffs read the PR iteration's merge-base/source files and compare text locally. PR title/description updates use structured JSON (stdin for GitHub and a private temporary file for Azure) and check the previously read revision. Provider errors remain visible and never fall back to another forge or account. No tokens are copied into workspace packets.

## Workspace transport

`codex-webrtc-voice-v1` adds `chatVoiceStart`, `chatVoiceHeartbeat`, `chatVoiceStop`, and `chatVoiceEvent` to the authenticated chat permission. A dedicated workspace connection owns the voice lease and App Server session. `AgentRPC(chatGPTOnly: true)` removes Platform-key environment variables; `account/read` must report `chatgpt` before any call. Effective project configuration is checked for custom OpenAI-provider key/bearer/authorization overrides; such configurations are rejected rather than used for voice. Saved threads are resumed with the OpenAI provider, workspace-write sandbox and on-request approvals. Fresh threads already loaded in the same App Server need no resume. The Mac's `CodexAccountController` uses `account/read`, `account/login/start` with `type: chatgpt`, login completion notifications and cancellation. Codex owns credential storage and refresh; no tokens are forwarded.

The protocol is generated from Codex **0.164.0** with `codex app-server generate-json-schema --experimental`. Initialization opts into `experimentalApi`. `thread/realtime/start` sends `threadId`, `outputModality: audio`, `version: v3`, `transport: {type: webrtc, sdp: offer}`, `realtimeSessionId` and `voiceSessionId`. Startup waits for both `thread/realtime/started` and the actual `thread/realtime/sdp` answer notification, in either order. The WebRTC default v1 was rejected by AVAS with `invalid_quicksilver_alpha_header`; v3 makes Codex itself select its Frameless Bidi parser, model and `quicksilver=v2` header. No manual authentication headers, internal client identities or attestation are supplied. See the version-pinned [realtime source](https://github.com/openai/codex/blob/rust-v0.164.0/codex-rs/core/src/realtime_conversation.rs) and [call authentication implementation](https://github.com/openai/codex/blob/rust-v0.164.0/codex-rs/core/src/client.rs).

`NocturneVoice.CodexVoicePeer` owns a native `RTCPeerConnection`, microphone track, remote audio track and `oai-events` data channel, using the checksum-verified WebRTC 155.0.0 Swift package. App Server has no trickle-ICE method in this version, so the peer waits for ICE gathering to complete before sending its local SDP. Only signaling passes through the workspace; PCM forwarding, public Realtime API calls and optional voice keys have been removed. Transcripts and automatic Codex worker/tool events remain attached to the selected thread. Canonical transcript items take precedence over compatibility transcripts, and approvals return on the connection that owns the request. Native media must connect as well as App Server before the UI becomes active.

WebRTC's duplex audio session supplies echo cancellation and playout; muting disables its outgoing track. The iOS audio background mode and retained parent workspace keep established calls alive in the background. Pending startup is cancelled when leaving the app. SDL desktop-stream teardown is followed by voice audio-session reactivation. Interruptions, media failure, revoked access, disconnect or hangup close tracks/data channels/peer and restore the previous audio configuration. A ten-second host heartbeat lease reaps abandoned calls. Simulator lifecycle checks do not establish physical locked-screen behavior.

A real test with ChatGPT login and no Platform-key environment built the v3 WebRTC call, sent synthetic speech, caused the Codex agent to read a disposable `voice-probe.txt`, and received the spoken verification number **427**. Native-offer/App Server signaling is also checked by the opt-in Swift integration test. The audio/agent test uses a real WebRTC peer harness rather than a physical iPhone microphone; evidence and reproduction instructions are in [development notes](DEVELOPMENT.md).

`NocturneKit` provides bounded JSON framing, TLS-PSK, Keychain storage, request deadlines, transfer state, and adaptive layout rules. Every connection requires a versioned hello. `NocturneHostKit` provides the host listener, `openat`/`O_NOFOLLOW` folder access, atomic no-overwrite uploads, real PTYs, and embedded-engine management. Partial transfers are cleaned up on disconnect or permission revocation. Up to 32 workspace connections and two uploads per connection are accepted, including dedicated app-window and microphone sockets. Terminal lifetime belongs to `WorkspaceServer` through `TerminalRegistry`, independently of those connections. Up to eight terminal tabs (running or ended) are retained per authenticated device certificate. Every list/attach/input/resize/close operation checks that owner; reconnecting cannot bypass the limit.

Protocol 3 adds terminal listing/attachment and per-tab metadata. Every output event carries a byte offset. Attachment atomically subscribes the connection and returns the retained suffix; the client appends only missing bytes, or resets its renderer when the requested offset has expired. The replay buffer is bounded to 512 KiB per tab and fits within the frame limit after JSON/base64 encoding. The server keeps draining PTYs while detached, and drains final output before marking an exited tab ended. Nothing is persisted to disk, and neither shells nor output survive a server restart.

Disconnect only removes that socket’s output subscriptions. Explicit tab close terminates one shell; Terminal permission revocation, Stop/Quit, or device removal closes the corresponding registry entries, including detached ones. A client reconnect lists and attaches existing tabs without opening replacement shells. Client buffers and selection survive a transport disconnect and are cleared when forgetting or switching the paired server.

The iOS app has no cloud service or account dependency. Its UIKit scene delegate disconnects the workspace transport when backgrounded unless an established voice call needs it. Server-owned shells remain running; the app reconnects and restores tabs when active, and keeps credentials out of ordinary preferences. A production distribution should use consistent Developer ID/device signing; these local builds are development artifacts.
